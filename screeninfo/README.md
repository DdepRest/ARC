# screeninfo — снимки экранов A.R.C.

Набор скриншотов всех рабочих пространств запущенного приложения A.R.C. (Electron, dev-режим).

## Как сняты

* Приложение запущено из рабочего дерева: `npx electron-vite dev --remoteDebuggingPort 9222`
  (Vite-сервер рендерера поднялся на `http://127.0.0.1:3001`, порт 3000 был занят другим процессом).
* Захват — через `agent-browser`, подключённый к Electron по CDP (`agent-browser --cdp 9222 ...`),
  то есть снимается сам кадр рендерера, а не весь рабочий стол.
* Окно — штатное `1280×800` (не развёрнуто), `frame: false`.
* Переход по вкладкам выполнен через стор приложения (`useUIStore().setActiveTab`),
  после переключения выдерживалась пауза на анимацию панели проекции.

Повторить съёмку: `bash screeninfo/capture-workspaces.sh`

## Замечания (состояние на момент съёмки)

1. **FILES** показывает `PATH_NOT_ALLOWED` / «Рабочая область не определена» — рабочая
   директория не задана, поэтому пространство пустое. Это состояние настроек, а не дефект снимка.
2. **MEMORY** пуста (нет записей долговременной памяти), **VISION** — оптика выключена.
3. **Дропдаун «Подсистемы A.R.C.» (_13_)** при штатной нижней позиции таб-бара не отображается:
   меню рендерится выше дока и полностью обрезается `overflow-hidden` контейнера `#arc-dock-container`
   (видимая полоса пересечения отрицательная). Кадр снят с временно переключённой верхней позицией
   таб-бара, после съёмки настройка возвращена в `bottom`. Правка в рамках этой задачи не выполнялась.
4. **Ctrl+K** для spotlight в dev-сборке не срабатывает; окно открыто штатным событием
   `open-spotlight`, которое использует сама кнопка «ПОИСК ⌘K».
5. Захват оверлеев виден только когда окно Electron находится на переднем плане — при перекрытом
   окне Chromium не перерисовывает свежую оверлейную поверхность, и кадр остаётся старым.

## Проверка

`node screeninfo/verify-shots.js screeninfo` печатает размеры, среднюю яркость, долю «засвеченных»
пикселей и md5 каждого файла (дубликаты помечаются как `DUP-OF`).
