# Дорожная карта развития A.R.C. (Development Roadmap)

Документ описывает стратегический и технический план развития архитектуры, визуализации и функциональных возможностей системы **A.R.C.** (Autonomous Reactive Companion).

---

## Этап 1. Совершенствование текущего функционала и UX

### 1.1 Интеграция 3D-Ядра (Reactor Core) с системными метриками
* **Цель**: Сделать анимацию ядра информативным индикатором состояния устройства.
* **Технические задачи**:
  - Внедрить получение системных метрик через Node.js/Electron API (загрузка CPU, использование RAM, температура, активность сети).
  - Связать частоту вращения внешних колец (`ringGroup.rotation`) с процентом загрузки CPU.
  - Связать пульсацию фонового свечения и анодированных элементов с использованием RAM.
  - Реализовать плавающее переключение цветов свечения ядра при критических нагрузках (>85% CPU/RAM).

### 1.2 Менеджер ИИ-моделей в UI
* **Цель**: Автоматизировать установку и переключение моделей STT (Sherpa-ONNX) и TTS (Silero) из интерфейса настроек.
* **Технические задачи**:
  - Создать раздел управления моделями в `QuickCoreSection.vue` / `SettingsView.vue`.
  - Реализовать загрузку модели по ссылке с прогресс-баром и валидацией контрольных сумм.
  - Добавить автоматическую проверку целостности файлов моделей (`encoder.onnx`, `decoder.onnx`, `tokens.txt`, `v5_5_ru.pt`).
  - Реализовать бешовное переключение моделей без перезапуска приложения.

### 1.3 Глубокая настройка голоса (TTS Engine Fine-Tuning)
* **Цель**: Расширить управление синтезом речи для Silero TTS v5.5.
* **Технические задачи**:
  - Добавить элементы управления (`sliders`): Скорость речи (`speed`), Высота тона (`pitch`), Частота дискретизации (`sample_rate`), Авто-ударение (`put_accent`, `put_yo`).
  - Выбор встроенных спикеров Silero (kseniya, baya, aidar, eugene, xenia).
  - Предпросмотр голоса ("Тестовая фраза") с немедленным воспроизведением.

### 1.4 Sci-Fi Терминал и Терминальный Лог (Reactor HUD & Logs)
* **Цель**: Визуализировать мыслительный процесс А.Р.К. рядом с 3D-реактором.
* **Технические задачи**:
  - Разработать плавающий виджет `ReactorTerminalOverlay.vue` в стиле голографического HUD.
  - Потоковый вывод транскрипции STT, внутренних решений агента, вызова функций и системных предупреждений.
  - Фильтрация логов по уровням (INFO, VOICE, EXEC, ERROR) и возможность быстрого копирования.

## Этап 2. Агентивность, Интеграции и Мультимодальность

### 2.1 Долгосрочная память (Long-Term Memory & RAG)
* **Цель**: Сохранение фактов о пользователе, контексте диалогов и прошлых задачах между сессиями.
* **Технические задачи**:
  - Внедрение SQLite таблицы `memories` с индексацией семантических эмбеддингов.
  - Локальная генерация эмбеддингов через легкую ONNX-модель или встроенный сервис.
  - Извлечение релевантных воспоминаний перед отправкой контекста в LLM.
  - Интерфейс просмотра и управления памятью ("Что А.Р.К. знает обо мне").

### 2.2 Система Навыков и Плагинов (Skills Framework)
* **Цель**: Расширение возможностей А.Р.К. по взаимодействию с внешним миром и ОС.
* **Технические задачи**:
  - **Модуль веб-поиска**: Поиск свежей информации и парсинг результативных страниц.
  - **Управление ОС**: Регулировка громкости, управление медиапроигрывателем, запуск приложений и мониторинг процессов.
  - **Интеграция с Умным Домом**: Поддержка Home Assistant REST API / MQTT для управления устройствами.

### 2.3 Мультимодальность и Визуальный Анализ (Vision & Screen Capture)
* **Цель**: Способность А.Р.К. "видеть" экран пользователя и анализировать изображения.
* **Технические задачи**:
  - Drag-and-Drop загрузка изображений и скриншотов в окно чата.
  - Горячая клавиша быстрого снимка выделенной области экрана (Quick Screen Capture).
  - Передача изображений в мультимодальные модели (Gemini Vision / local multimodal) для анализа ошибок на экране и подсказок.

### 2.4 Расширенная система автономных задач (Autonomous Objective Engine)
* **Цель**: Автономное решение комплексных задач с гарантией безопасности.
* **Технические задачи**:
  - Пошаговое планирование (Multi-step agent loop) на базе `PolicyEngine` и `SandboxedFS`.
  - Автоматическая генерация и запуск тестовых скриптов в изолированной песочнице.
  - Система утверждения действий (`RouteApproval`): Запрос подтверждения у пользователя перед выполнением потенциально опасных команд (запись файлов, сетевые запросы).

## Этап 3. Архитектура, Автономность и Оптимизация

### 3.1 Адаптивная оптимизация 3D-реактора (Dynamic Performance Scaling)
* **Цель**: Гарантия стабильных 60+ FPS на любых видеокартах.
* **Технические задачи**:
  - Внедрить монитор производительности (FPS counter) на базе `requestAnimationFrame`.
  - При снижении FPS ниже 45: автоматическое снижение пиксельного соотношения (`devicePixelRatio`), отключение Bokeh/Post-processing эффектов.
  - Ручные пресеты качества графики: Low (минимальное число частиц, без теней), Medium, Ultra.

### 3.2 Поддержка локальных автономных LLM (Offline LLM Engine)
* **Цель**: Полная независимость от интернет-соединения и внешних облачных API.
* **Технические задачи**:
  - Интеграция REST/WebSocket клиента для взаимодействия с локальным сервером **Ollama** / **llama.cpp**.
  - Переключатель источника LLM в настройках (Cloud API / Local Ollama).
  - Автоматический fallback на локальную модель при отсутствии интернет-соединения.
