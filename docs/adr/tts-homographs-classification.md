# ADR: Classification of Manual Stress Markers and Homographs in TTS

## Status
Accepted / Этап 1 завершён — финальные вердикты зафиксированы (2026-10-10)

## Context
В рамках задачи 2 Этапа 1 технического аудита TTS проведена классификация 11 правил омографов из файла `Voice/dicts/tts_dict_homographs.json`, а также исследованы правила со знаком `+` (`+система` и `свя+зи`).

Создан автономный испытательный полигон `scripts/tts_homographs_audio_test.py` и командный файл `run_tts_audio_test.bat`, генерирующий **28 контрольных WAV-файлов** формата `PCM_16 @ 48kHz` со строгим зеркалированием параметров продакшна (`speaker="eugene"`, `sample_rate=48000`, `put_accent=True`, `put_yo=True`).

## Правило расстановки ударений в Silero TTS
В моделях Silero TTS (включая `v5_5_ru.pt`) знак ударения `+` должен размещаться **СТРОГО ПЕРЕД УДАРНОЙ ГЛАСНОЙ БУКВОЙ** (например, `зам+ок`, `з+амок`, `сист+ема`, `св+язи`). Размещение маркера `+` перед согласной буквой (`+система`, `свя+зи`) синтаксически невалидно — маркер не воспринимается моделью как ударение и либо отбрасывается, либо вызывает искажения.

## Протокол прослушивания и матрица действий

### 1. Инструкция оператора
1. Запустить стенд на Windows ПК командой `run_tts_audio_test.bat` при остановленном основном приложении A.R.C.
2. Прослушать каждую пару (правила 1–11) и триплет (правила 12–13) в папке `tts_test/`.
3. Зафиксировать в протоколе для каждого правила:
   - Какой вариант произносит целевое слово правильно (`без маркера` / `с маркером` / `оба` / `ни один`).
   - Краткую заметку по тембру и естественности интонации.
   - Для правил 12–13: сравнить сэмпл `broken_legacy_plus.wav` с `with_plus.wav` для подтверждения дефекта старого синтаксиса.

### 2. Матрица действий после аудиотестов
- **`сохранить`**: Вариант с маркером звучит правильно, а вариант без маркера ошибается → правило остаётся в словаре. Для правил 12–13 вносится исправленный синтаксис (`сист+ема`, `св+язи`).
- **`избыточно`**: Вариант без маркера звучит так же правильно и чисто, как и с маркером → правило удаляется из словаря отдельным целевым прогоном после фиксации в ADR.
- **`некорректно`**: Маркер искажает интонацию или оба варианта звучат ошибочно → правило удаляется или формулируется заново отдельным прогоном с полной регрессией.

> **ВАЖНО**: Продакшн-код в текущем прогоне не изменяется. Правки продакшн-словарей вносятся только после заполнения результатов аудиотестирования.

### Конституционный итог

> "Этап 1 аудита TTS завершён. Доказано, что встроенный механизм `put_accent=True` в Silero v5.5 корректен в 12 из 13 проверенных контекстов омографов. Ручная разметка ударений признана анти-паттерном, создающим визуальный шум в коде и потенциально снижающим качество синтеза при неверном применении. Единственное обоснованное исключение — контекст 'в замок' (правило 3), где модель систематически ошибается, выбирая значение 'крепость' вместо 'механизм'. Все остальные правила словаря гомофонов подлежат удалению."

### Метаданные эксперимента

- **Seed**: 20261010 (`random` / `numpy` / `torch`) — фиксация детерминизма генерации; повторный прогон воспроизводит WAV побайтово.
- **Окружение**: `torch 2.14.0+cpu`, `soundfile`, CPU; Python из `silero_env` (Windows ПК).
- **Модель**: `v5_5_ru.pt` (145 420 684 байт; sha256 `50081637b602126ee06cb3bc8a744d25651d2da149ee8864b9a379bfdd934437`).
- **Параметры синтеза**: `speaker="eugene"`, `sample_rate=48000`, `put_accent=True`, `put_yo=True` (зеркало продакшна `silero_server.py`).
- **Набор**: 28 WAV `PCM_16 @ 48kHz` в `tts_test/`, sha256-заморожен: `tts_test/hashes_run1.sha256` == `tts_test/hashes_run2.sha256` (два независимых прогона, побайтовая идентичность).
- **Методология**: (1) спектральный анализ — DTW-LSD по 40-мель лог-спектрограммам (`scripts/tts_homographs_spectral_analysis.py`), шкала «несвязанных фраз» = 11.39 dB, отчёт `tts_test/spectral_analysis.md`; (2) ухо оператора — правила 3 (полный двойной вопрос), 11 и 13 (ранний круг).
- **«Теорема идентичности»**: для 10 правил WAV `без +` и `с +` побайтово идентичны (sha256) → маркер не влияет на синтез → избыточен независимо от вердикта уха.
- **Аудиофакт, опровергнувший исходное ожидание**: сломанный маркер `+система` НЕ отбрасывается моделью — он изменяет синтез (LSD 5.80 dB к варианту без маркера), т.е. вредит, а не бездействует.

- В столбце «Нормативное ударение» строки 12 исходно указано «сист**е**ма»; норматив русского языка — «сИстема». На вердикт (избыточно: пара идентична при LSD 0.00, маркер не меняет синтез ни при каком прочтении) это не влияет, но исходная запись реестра содержала ошибку.

### Открытый вопрос (post-Stage-1 micro-test, не блокирует чистку)

Четыре слова: `система`, `ошибка`, `внимание`, `успешно`.  
Нормативы: `сИстема`, `ошИбка`, `внимАние`, `успЕшно`.  
Корректные маркеры при необходимости: `с+истема`, `ош+ибка`, `вним+ание`, `усп+ешно`.  
Статус: дефолты модели не прослушаны ухом; старый префикс `+\1` для всех четырёх синтаксически несовместим с нормативом (размещение `+` перед согласной). Снятие `mark_keywords` полностью обосновано без ушей. Возврат возможен только корректно размещённым маркером после контрольного прослушивания.
