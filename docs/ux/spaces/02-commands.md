## 3. Дефекты

| # | Дефект | Доказательство | Влияние |

| D1 | **Динамические классы Tailwind из переменной.** Акцент карточки макроса собирается строкой: `` `border-${settingsStore.reactorColorTheme}-500/20` ``, `` `bg-${...}-500/10` ``, `` `text-${...}-400` ``. Tailwind сканирует исходники статически, поэтому такие классы в сборку не попадают — цветовая реакция карточки на тему ядра не работает | `SkillsTab.vue` (карточка макроса) | высокое |
| D2 | Редактор макросов — сплошной чёрный экран на весь интерфейс (`fixed inset-0 ... bg-black`), перекрывающий вкладки и оболочку; конституция запрещает глухой чёрный фон | `MacroEditorView.vue:2` | высокое |
| D3 | Стили LiteGraph переопределяются глобальным блоком без `scoped`: 20+ правил с `!important`, хардкод `rgba(8,8,12,0.95)`, `z-index: 99999` — внешняя библиотека получает приоритет над дизайн-системой | `MacroEditorView.vue` (блок `<style>` без `scoped`) | среднее |

## 4. Что сделано хорошо

1. **Вкладка навыков использует примитивы** (`ArcInput`, `ArcButton`, `ArcToggle`, `ArcChip`) — пространство в верхней части списка по дисциплине дизайн-системы.
2. **Правильные роли для под-вкладок:** `role="tablist"` + `role="tab"` + `aria-selected` — один из двух таких случаев в проекте (второй — `TabBar`).
3. **Пустое состояние редактора макросов** — с шаблонами быстрого старта: пустой экран превращён в точку входа, а не в тупик.
4. **Графический редактор вынесен из каркаса** в отдельный компонент с палитрой и панелью свойств — структура правильная, вопрос только в оформлении.
5. **Разделение реестра и лаунчера** по под-вкладкам: три разные задачи не смешаны на одном экране.
