**Дата:** 19.09.2026

## 1. Паспорт

- **Назначение:** основной канал диалога с ядром — история сообщений, вложения, потоковая генерация, трейс выполнения инструментов.
- **Состав:**
  - `ChatView.vue` (380) — каркас пространства, список сообщений, drag&drop вложений, автоскролл;
  - `ChatStatusBar.vue` — статус диалога и активная модель;
  - `MessageBubble.vue` (372) — сообщение, лайтбокс вложений, парсинг markdown;
  - `ChatInputZone.vue` (366) — поле ввода, выбор файлов, микрофон;
  - `ExecutionTrace.vue`, `ValidatorRejectionCard.vue`, `MessageFooter.vue` — трейс шагов, отказ валидатора, источники;
  - `SessionSidebar.vue` (422, whitelisted), `SessionContextMenu.vue` — история сессий;
  - `composables/useChat.ts` (392), `stores/sessions.store.ts` (364), `stores/chat.store.ts` (243), `utils/markdown.ts` — логика.
- **Владелец идентичности:** оболочка (CommandCenter/TabBar). В самом пространстве собственного заголовка нет — это правильно.

## 3. Дефекты

| # | Дефект | Доказательство | Влияние |
|---|---|---|---|
| D1 | Микрофон работает через **браузерный** `webkitSpeechRecognition`, а не через собственный STT-стек проекта (Sherpa/GigaAM/Whisper); при отсутствии API запись имитируется таймером на 2 с — кнопка пульсирует и ничего не делает | `ChatInputZone.vue:209-243` (особенно `:212`, `:243`) | высокое |
| D2 | Автоскролл вниз без проверки положения: срабатывает на **любое** обновление компонента, из-за чего чтение истории сбрасывается во время потоковой генерации и любых перерисовок | `ChatView.vue:371`, `:367-368` | высокое |
| D3 | `select-none` на корне пространства; ни в `ChatView`, ни в `MessageBubble` нет ни одного `select-text` — выделение текста ответа под вопросом и требует проверки в запущенном приложении | `ChatView.vue:3` | высокое |
| D4 | Два независимых пайплайна вложений: одинаковые `readFileAsText`/`readFileAsDataURL`/`processSelectedFiles` в двух компонентах, ошибки чтения гасятся в консоль | `ChatView.vue` и `ChatInputZone.vue` | среднее |
| D5 | Плейсхолдер выбирается через `Math.random()` и содержит стареющие примеры с датами — подсказка меняется при каждом входе и обесценивается | `ChatInputZone.vue:153-168` | среднее |
| D6 | При отсутствии выбранной модели в статусе показывается `A.R.C. Neural Core` — модель, которой не существует | `ChatStatusBar.vue:140` | среднее |
| D7 | Ошибочный/системный блок определяется регуляркой по тексту (`/ошибка\|сбой\|error\|failed/i`), из-за чего обычный ответ, объясняющий ошибку, помечается как системная ошибка | `MessageBubble.vue` (`isErrorStatus`) | среднее |
| D8 | Панель действий сообщения (озвучить/перегенерировать/копировать/удалить) появляется поверх текста при наведении и перекрывает верхние строки ответа | `MessageBubble.vue` | низкое |
| D9 | Лайтбокс вложений — собственный оверлей с плотным фоном (`bg-black/90`), без фокуса, ролей и Escape; рядом с ним контекстное меню сессии — второй самодельный слой | `MessageBubble.vue`, `SessionContextMenu.vue` | среднее |
| D10 | Удаление сообщения выполняется без подтверждения и без отмены, при этом чат — единственное пространство, где сообщение исчезает мгновенно | `MessageBubble.vue` (`$emit('delete')`) | низкое |
| D11 | Потолок файлов: `MessageBubble` 372, `ChatInputZone` 366, `ChatView` 380 — следующая правка в любом из них требует предварительного выноса логики | `[замер]` | среднее |

## 4. Что сделано хорошо

1. **Трейс фильтрует синтетические шаги** (`realExecutionSteps`): показываются только реальные внешние вызовы, а не внутренние «анализ директивы / синтез ответа». Это ровно та честность, которой не хватает другим пространствам.
2. **Отказ валидатора — отдельная карточка с действиями** (`ValidatorRejectionCard`: retry/refine), а не просто текст ошибки.
3. **Markdown санитизируется** (`sanitizeRawContent` + `parseMarkdown`) и парсится с троттлингом при потоковой генерации — интерфейс не перерисовывает документ на каждый токен.
4. **Копирование имеет три пути деградации** (`window.api.writeClipboard` → `navigator.clipboard` → `execCommand`) и сообщает пользователю об успехе или сбое.
5. **Источники ответа** вынесены в `MessageFooter` — атрибуция инструментов видна без раскрытия трейса.
