# F1 — Дизайн-система и токены

**Фронт:** первый. **Опирается на:** ничего. **От него зависят:** F2, F3, F6 и все пространства.
**Основание:** [`../01-vision.md`](../01-vision.md) (слои L0–L2), [`../02-global-audit.md`](../02-global-audit.md) (дефекты C1–C5).

## 1. Задача фронта

Сделать так, чтобы **структура** интерфейса, а не дисциплина авторов, удерживала единый вид.

Аудит показал: система уже спроектирована (81 токен в `tokens.css`, включая полную ролевую палитру A.R.C. RED), но интерфейс ею не пользуется — 351 сырой `<button>` против 37 `ArcButton`, 194 хардкода длительности против 2 обращений к токенам движения, ноль токенов слоёв, 24 копии стилей скроллбара и плотный чёрный фон вместо стекла в 15 файлах (при одном корректном применении стекла в `ArcModal`). Значит работа не в создании системы, а в её **внедрении и защите от обхода**.

Целевое состояние: правка на уровне L0 меняет интерфейс везде; новый экран не может незаметно выпасть из системы, потому что это ловит сборка.

## 3. F1.1 — Шкала слоёв

Сейчас значения слоёв разбросаны от `z-10` до `z-[200000]` (SyncToast), включая `z-[100001]` (загрузка моделей), `z-[50000]` (модалки), `z-9999` (подтверждение команд), `z-35` (слой виджетов). Особенность: Tailwind 4 поддерживает пространство `--z-index-*` в теме, поэтому токены станут настоящими утилитами (`z-modal`, `z-toast`) — это проверено по исходнику установленной версии (4.3.3).

Предлагаемая шкала (девять ролей, больше не нужно):

| Токен | Значение | Кто использует |
|---|---|---|
| `--z-index-base` | 0 | Обычное содержимое |
| `--z-index-dock` | 10 | Command Dock, нижние панели |
| `--z-index-sticky` | 20 | Закреплённые заголовки внутри пространств |
| `--z-index-panel` | 30 | Выдвижные панели, боковые рейлы, слой виджетов |
| `--z-index-overlay` | 40 | Служебные оверлеи поверх пространства |
| `--z-index-modal` | 50 | Окна и подтверждения (ArcModal, ApprovalDialog) |
| `--z-index-popover` | 60 | Выпадающие меню, календарь, подсказки |
| `--z-index-toast` | 70 | Уведомления и тосты |
| `--z-index-critical` | 80 | Только критические системные баннеры (нехватка памяти и подобное) |

Таблица миграции: `z-[200000]`→`z-toast`, `z-[100001]`→`z-modal` (оверлей загрузки) либо `z-critical` при блокирующем характере, `z-[50000]`→`z-modal`, `z-[9999]`→`z-modal`, `z-35`→`z-panel`, `z-50` (дропдауны) →`z-popover`, локальные `z-40`→`z-overlay`.

**Правило:** локальные числовые слои в шаблонах запрещены; исключение возможно только с комментарием, объясняющим, почему роли не хватило.

## 4. F1.2 — Движение

Уже есть: `--motion-ui-fast` (200 мс), `--motion-ui-state` (300 мс), `--motion-reactor` (700 мс) — все на одной кривой `cubic-bezier(0.2, 0.8, 0.2, 1)`. Используются 2 раза.

Дополняем ролями и исключаем «магические» кривые из шаблонов:

| Роль | Назначение |
|---|---|
| `--motion-hover` | отклик наведения (быстро, без задержки) |
| `--motion-ui-fast` | микровзаимодействия: нажатие, переключение (существует) |
| `--motion-ui-state` | смена состояния панели (существует) |
| `--motion-enter` | появление окна/элемента |
| `--motion-exit` | исчезновение (короче появления) |
| `--motion-reactor` | только Реактор (существует, неприкосновенен) |

**Правило приоритета Реактора (из видения):** выразительный медленный ритм принадлежит ядру. Интерфейс вокруг пользуется только ролями до 300 мс. Это сохраняет главенство Реактора из конституции и убирает ощущение «прыгающего» интерфейса.

## 5. F1.3 — Типографические роли

Сегодня каждый экран выбирает размер сам: `text-2xl md:text-3xl` в целях, `text-base md:text-lg` в формах, `text-[10px] uppercase font-mono` даже для человекочитаемых описаний (например, в пустом состоянии). Вводим роли вместо свободных значений:

**Human Layer** (гротеск, нормальный регистр, читаемость):

| Класс | Назначение |
|---|---|
| `.arc-title-space` | Название пространства (владеет оболочка) |
| `.arc-title-section` | Заголовок блока внутри пространства |
| `.arc-row-title` | Название параметра, элемента списка |
| `.arc-row-desc` | Описание, подсказка, пояснение |
| `.arc-body` | Текст содержания (сообщения, задачи, описания) |

**Machine Layer** (моноширинный, разрядка, верхний регистр — только для метаданных):

| Класс | Назначение |
|---|---|
| `.arc-label` | Категория, статус, бейдж |
| `.arc-value` | Числовое значение, тайминг, процент |
| `.arc-id` | Идентификатор, код, адрес, модель |

**Правило:** человекочитаемый текст не может быть оформлен ролями Машинного слоя. Именно это нарушение делает описания и подсказки «технической пылью».

## 7. F1.5 — Служебный слой

Дублирование служебных стилей — самая массовая проблема аудита: стили скроллбара продублированы в **24 файлах**, собственная вуаль описана в каждом из **10 файлов** с самодельным оверлеем (11-й слой — сам `ArcModal`), а вместо стекла «Истинное Стекло» в **15 файлах** стоит плотный чёрный фон (19 вхождений `bg-black/85…95`) — при том что корректное стекло `bg-[#070709]/65` используется в проекте **один раз** (в самом `ArcModal`). Фокус-кольцо прописано точечно.

Вводим единые утилиты в `global.css` (не новый файл — файл стилей уже существует и подключён):

| Утилита | Заменяет |
|---|---|
| `.arc-scrollbar` | 24 локальных блока `::-webkit-scrollbar` |
| `.arc-glass-panel` | плотный чёрный фон вместо стекла (19 вхождений в 15 файлах); значения по конституции: `bg-[#070709]/65` + `backdrop-blur-2xl` + тонкая граница |
| `.arc-veil` | 10 локальных описаний затемнения (11-й слой — сам `ArcModal` как эталон); по конституции `bg-black/30 backdrop-blur-sm` |
| `.arc-focus-ring` | разрозненные `focus:ring-*` и `focus:outline-none` без замены |
| `.arc-glow-accent` | повторяющиеся `shadow-[var(--accent-glow)]` |

Отдельно фиксируется запрет: **`focus:outline-none` без видимого фокус-кольца недопустим** — это одновременно и качество, и доступность (связка с F6).

## 9. F1.7 — Защёлка дисциплины

Идея: не требовать одномоментного исправления долга, но запретить его рост.

**Механика.** Скрипт `scripts/check-ui-consistency.js` читает файл-фон `scripts/ui-consistency-baseline.json` с текущими значениями и сравнивает:

```jsonc
{
  "rawButtons": 351, "rawInputs": 56, "rawSelects": 16,
  "hardcodedAccentHex": 315, "hardcodedDurations": 194,
  "opaqueBlackBackgrounds": 19, "nativeDialogs": 17,
  "emojiInChrome": 103, "numericZLiterals": 129,
  "duplicatedScrollbarBlocks": 24
}
```

Все значения в примере — реальные замеры аудита от 19.09.2026, а не иллюстрация. `numericZLiterals` — все числовые слои в шаблонах (129 обращений, из них 14 — произвольные `z-[...]`); после внедрения токенов счётчик должен уменьшаться.

Правила проверки: любое значение **больше** базового — ошибка сборки; меньше — печатается как прогресс и **обновляет** базовый файл отдельной ручной командой (`npm run ui:baseline`), чтобы уменьшение долга фиксировалось осознанно, а не автоматически.

**Почему это правильно:** долг измеряется честно, новые нарушения невозможны, давление на разовую глобальную замену отсутствует. Скрипт подключается в `npm run gate` и в `npm run build` рядом с проверкой размеров.

## 10. F1.8 — Галерея примитивов

Служебный экран, который показывает каждый `Arc*` во всех обязательных состояниях: обычное, наведение, фокус, нажатие, отключено, загрузка, ошибка, длинный текст, пустое значение.

**Зачем:** сейчас расхождение между экранами обнаруживается только тем, что кто-то заметил. Галерея превращает это в десятисекундную проверку и становится эталоном для будущих визуальных снапшотов (этап IV видения).

**Доступ:** через палитру команд (`SpotlightSearch`) и/или раздел диагностики в Settings. Экран помечается как служебный и не входит в основную навигацию.

## 11. F1.9 — Порядок миграции

Порядок выбран так, чтобы первые шаги давали эффект сразу и были безопасными (механическими), а рискованные шли позже и по одному пространству.

| Шаг | Что делаем | Риск | Пространства |
|---|---|---|---|
| 1 | `.arc-scrollbar` вместо 24 копий | Низкий | все |
| 2 | Цветовые роли вместо хардкода | Низкий | все |
| 3 | Роли движения вместо `duration-*` | Низкий | все |
| 4 | Слои по шкале | Средний (проверить наложение) | оверлеи и окна |
| 5 | Типографические роли | Средний (меняет вид) | по пространству |
| 6 | Кнопки и поля на примитивы | Средний | по пространству |
| 7 | Бейджи, чипы, подсказки | Низкий | по пространству |

Один шаг — одна итерация с проверками из дорожной карты. Шаги 6–7 не выполняются внутри файлов, запланированных к переработке в [`../04-tasks-settings.md`](../04-tasks-settings.md), — там примитивы применяются по ходу работ.

## 12. Definition of Done фронта

1. Токены слоёв, движения, типографики и цвета описаны и используются минимум в одном пространстве как эталон (рекомендую Settings: там уже инженерная подача).
2. Скроллбар, стекло, вуаль и фокус-кольцо существуют в единственном экземпляре.
3. `ArcBadge` и `GlassPanel` либо задействованы, либо удалены; `EmptyState` приведён к Human Layer.
4. Защёлка дисциплины запускается, не падает на текущем состоянии и подключена в сборку.
5. Галерея примитивов доступна и показывает все состояния.
6. Опубликованная таблица миграции покрывает все шаги 1–7.

## 14. Риски и их снятие

| Риск | Снятие |
|---|---|
| Массовая замена ломает вид десятков экранов | Замена по пространствам; после каждого — ручная проверка через `arc.bat` |
| Токены движения затрагивают Реактор | Реактор использует только `--motion-reactor`; правки ядра запрещены конституцией |
| Смена слоёв ломает наложение (тост под окном, дропдаун за панелью) | Отдельная итерация шага 4 с ручным сценарием: открыть окно → открыть дропдаун → показать тост → закрыть окно |
| Защёлка блокирует работу из-за ложных срабатываний | Базовый файл фиксируется вручную; проверка допускает исключения с комментарием `ui-allow` |
| Галерея превращается в мёртвый экран | Включить в обязательный шаг проверки перед релизом (этап IV) |
