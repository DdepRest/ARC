# F2 — Окна, диалоги и обратная связь

**Фронт:** второй. **Опирается на:** F1 (примитивы, служебные классы, роли). **Влияет на:** все пространства.
**Основание:** [`../02-global-audit.md`](../02-global-audit.md) (дефекты C6, C7), [`../01-vision.md`](../01-vision.md) (L1/L2, правило честной ошибки).

---

## 1. Задача фронта

Сейчас оконный слой состоит из трёх несогласованных миров:

1. **Системный мир:** 17 вызовов `confirm`/`alert`/`prompt` в 7 файлах — блокируют рендерер и выпадают из визуальной системы.
2. **Самодельный мир:** 11 файлов имеют собственный слой `fixed inset-0` со своими затемнениями (от лёгкой вуали до `bg-black/70` и `bg-black/80`); из них один — сам `ArcModal` как примитив, то есть самодельных оверлеев десять.
3. **Системный примитив:** `ArcModal` (9 использований) — уже полностью соответствует конституции по стеклу, но без ловушки фокуса, без ролей доступности и с глобальным обработчиком Escape на каждом экземпляре.

Плюс отдельный слой проблем — **обратная связь:** 330 блоков `catch`, из них 209 пишут только в консоль, а пользовательских уведомлений всего 45. Сбой в загрузке модели, работе с файлами или сети часто выглядит как «ничего не произошло».

Целевое состояние: **одно окно, один фокус, один Escape — верхнее окно, ни одного системного диалога, ни одного молчащего сбоя в ключевых сценариях.**

## 3. F2.1 — Контракт окна (`ArcModal`)

Окно обязано гарантировать семь вещей:

| # | Гарантия | Как проверяется |
|---|---|---|
| 1 | Фокус при открытии уходит внутрь окна и не покидает его по Tab | Прогон клавиатурой |
| 2 | При закрытии фокус возвращается на элемент, который открыл окно | Прогон клавиатурой |
| 3 | Окно объявлено как диалог (`role="dialog"`, `aria-modal`, связь с заголовком) | Проверка ролей |
| 4 | Страница под окном не прокручивается | Скролл колесом под открытым окном |
| 5 | Escape закрывает **только верхнее** окно | Открыть два окна, нажать Escape один раз |
| 6 | Закрытие по клику на вуаль — управляемо (у диалогов подтверждения выключено) | Ручной сценарий |
| 7 | Вуаль и панель — по конституции (`bg-black/30 backdrop-blur-sm` / `bg-[#070709]/65 backdrop-blur-2xl`) | Визуальная проверка |

**Пункт 5 — это исправление дефекта:** сейчас каждый смонтированный экземпляр вешает обработчик на `window`, поэтому один Escape закрывает все открытые окна одновременно. Решение — единый стек открытых окон в диалоговом сервисе: обработчик один, закрывается верхнее.

## 4. F2.2 — Диалоговый сервис

Вместо того чтобы каждое пространство само решало, как спросить подтверждение, вводится один сервис (composable + точка монтирования в `App.vue`):

```
useDialog()
  ask({ title, message, confirmLabel, tone: 'normal' | 'dangerous' }): Promise<boolean>
  notify({ message, kind: 'success' | 'info' | 'critical', undo?: () => void }): void
```

Принципы:

1. **Тон подтверждения определяется риском.** Обычное действие — нейтральное окно; разрушающее (сброс, удаление, откат, очистка) — приглушённый акцент, явная формулировка последствий и кнопка подтверждения не по умолчанию в фокусе.
2. **Существующий слой уведомлений переиспользуется.** В проекте уже есть глобальный тост с отменой (`SyncToast` + `triggerSyncToast`) — сервис строится на нём, второй механизм не создаётся.
3. **Никаких новых глобальных обработчиков клавиш.** Стек Escape реализуется в сервисе, а не в каждом компоненте.
4. **Системный лог как «подробности».** Для критических ошибок в уведомлении остаётся ссылка на системный терминал — пользователь получает понятное сообщение, а технические детали не теряются.

## 5. F2.3 — Приоритет: диалог подтверждения команд

`ApprovalDialog` — подтверждение запуска системных команд, то есть самый ответственный диалог приложения. Сейчас он оформлен тяжелее и грубее остальных: затемнение `bg-black/70` и произвольный слой `z-9999` вместо лёгкой вуали и шкалы слоёв.

Работы по нему: вуаль `bg-black/30 backdrop-blur-sm`, слой по токену `--z-index-modal`, ловушка фокуса, явная формулировка «что именно будет выполнено», команда подтверждения — не в фокусе по умолчанию, закрытие по Escape — разрешено, по клику на вуаль — **запрещено** (случайное отклонение критичного подтверждения недопустимо).

Выполняется первым (до общей миграции оверлеев), потому что затрагивает безопасность.

## 7. F2.5 — Миграция самодельных оверлеев

Десять файлов строят собственный оверлей (одиннадцатый из найденных — сам `ArcModal`). Их надо разделить на два класса, потому что не всякий оверлей — диалог:

| Класс | Признак | Решение |
|---|---|---|
| **Диалог** (просит решение или показывает содержимое поверх всего) | Есть фон-вуаль, закрывается, блокирует взаимодействие с фоном | Переводится на `ArcModal` |
| **Служебный слой** (подсказка поиска, панель загрузки, слой виджетов, подтверждение при перетаскивании файла) | Часть интерфейса, а не модальное требование | Остаётся оверлеем, но получает роль слоя из шкалы F1 и общую вуаль |

Кандидаты: `SpotlightSearch`, `ModelDownloadOverlay`, `MessageBubble` (просмотр изображения), `SessionContextMenu`, `MacroEditorView`, `MemoryView`, `ApprovalDialog`, `FpsOverlay`, `WidgetsLayer`, `App.vue` (диалоги памяти и модели).
Отдельный случай — `StatusOverlay.vue`: это не оверлей, а закреплённая полоса поверх сцены; удаляется целиком в F4 вместе с мёртвым `FocusMode`.

## 8. F2.6 — Честная ошибка

Правило из видения: **любое действие, которое ходит за данными, заканчивается видимым исходом** — успех, ошибка или честное «в разработке». Молчащий `catch` приравнен к дефекту интерфейса.

Практика:

1. Ввести общий помощник сообщения о сбое, который принимает контекст действия и подсказку, что делать («Не удалось загрузить модель. Проверьте соединение. Подробности — в системном логе»).
2. Пройти ключевые сценарии: загрузка и переключение моделей, выбор микрофона, экспорт/импорт, работа с БД памяти, файловые операции, сетевые запросы провайдеров.
3. Внутренние, не пользовательские сбои (парсинг логов, вспомогательные вычисления) остаются в консоли — цель не «показать всё», а «не молчать там, где пользователь ждёт результат».
4. Критерий приёмки: для каждого ключевого сценария есть ручной сценарий «сломать и посмотреть» — выключить сеть, подсунуть битый JSON, отключить микрофон.

## 9. Definition of Done фронта

1. Ни одного системного диалога, кроме согласованного исключения в голосовом тракте.
2. Открыты два окна — один Escape закрывает верхнее, фокус возвращается корректно.
3. Все подтверждения идут через диалоговый сервис, тон соответствует риску.
4. `ApprovalDialog` соответствует и конституции, и контракту окна.
5. Все затемнения — `bg-black/30 backdrop-blur-sm`; все слои — по токенам F1.
6. В ключевых сценариях сбой виден пользователю; для каждого есть ручной сценарий проверки.

## 11. Риски и их снятие

| Риск | Снятие |
|---|---|
| Ловушка фокуса ломает существующие оверлеи, которые не диалоги | Флаг «диалог/слой»; фокус-ловушка включается только для диалогов |
| Блокировка скролла конфликтует с внутренним скроллом окна | Скролл блокируется у страницы, внутренние контейнеры окна сохраняют прокрутку |
| Диалоговый сервис дублирует существующий тост | Сервис — обёртка над существующим механизмом уведомлений с отменой |
| Показ ошибок превращается в шум | Правило разделения: пользовательские сценарии — видимо, внутренние — в лог |
| Единый обработчик Escape конфликтует с глобальными шорткатами | Стек окон имеет приоритет; Escape при пустом стеке передаётся дальше (закрытие проекции) |
