# F6 — Доступность и клавиатура

**Фронт:** шестой (после F1 и F2, чтобы не делать работу дважды).
**Основание:** [`../02-global-audit.md`](../02-global-audit.md) (дефект C8), [`../01-vision.md`](../01-vision.md) (пункт 5 контракта пространства).

---

## 1. Задача фронта

Замеры: на 148 компонентов — 16 `aria-label`, 11 `tabindex`, 16 `role`, ноль ловушек фокуса. Интерфейс сведён к мыши. Для desktop-среды, которая позиционирует себя как голосовая и командная консоль, это противоречие: там, где голос уместен, клавиатура обязана работать как минимум не хуже.

Целевое состояние: **ключевые сценарии выполнимы без мыши, фокус всегда видим и предсказуем, у окон и списков корректные роли, горячие клавиши описаны в одном месте и не конфликтуют.**

## 3. F6.1 — Фокус как часть системы

1. Фокус-кольцо описывается один раз (в служебном слое F1) и применяется всеми примитивами: тонкое свечение акцентной роли по контуру, без резкой рамки браузера.
2. Запрещено скрывать фокус без замены. Сейчас `focus:outline-none` встречается точечно и в части случаев не компенсирован.
3. Фокус виден и на тёмном стекле, и на акцентных кнопках.
4. Порядок фокуса соответствует визуальному порядку: сверху вниз, слева направо; закреплённые панели не «воруют» фокус.

---

## 4. F6.2 — Роли и подписи

| Что | Требование |
|---|---|
| Окна и подтверждения | `role="dialog"`, `aria-modal`, связь заголовка с окном (реализуется в F2.1) |
| Списки (задачи, сообщения, цели, файлы, история) | Корректные роли списка и элементов; текущий выбранный элемент объявлен |
| Иконочные кнопки | Подпись вместо браузерного `title`: сейчас `aria-label` есть лишь у 16 элементов, а кнопок — сотни |
| Статусы и счётчики | Значение доступно как текст, а не только цветом (например, приоритет `P1` читаем, а не только «красный») |
| Состояния загрузки | Объявление процесса («Загрузка модели, 42 процента») |
| Голосовые состояния | Состояние прослушивания и обработки выражено не только свечением Реактора — нужен текстовый/звуковой эквивалент для невизуального восприятия |

---

## 5. F6.3 — Клавиатурные сценарии

Порядок по ценности для пользователя:

| Пространство | Минимальный сценарий |
|---|---|
| Tasks | Навигация по списку, завершение, переименование, удаление с отменой, поиск, смена режима просмотра — **уже в плане** [`../04-tasks-settings.md`](../04-tasks-settings.md) |
| Chat | Переключение сессий, переход по истории, копирование ответа, отправка, отмена генерации |
| Memory | Навигация по узлам, поиск, создание, редактирование, удаление с отменой |
| Objectives | Навигация по списку целей и вехам, открытие деталей, декомпозиция |
| Commands | Поиск команды, запуск макроса, просмотр параметров |
| Settings | Перемещение по секциям и строкам, изменение значений (переключатели, шкалы), возврат к поиску |
| Файлы / Vision / Modules | Навигация по списку, открытие, действия |

Требование к каждому: работает без мыши, состояние фокуса заметно, действия не конфликтуют с глобальными сочетаниями.

---

## 6. F6.4 — Реестр горячих клавиш

Сейчас сочетания разбросаны: глобальный слой (`useCommandCenter`), локальные обработчики в компонентах, шорткаты внутри пространств. Итог — риск скрытых конфликтов, например между пробелом-микрофоном, Escape-закрытием и навигацией по списку.

Предлагается:

1. **Один реестр** (данные + небольшой модуль регистрации), где каждое сочетание описано: комбинация, область действия (глобально / пространство), действие, конфликтующие сочетания.
2. **Проверка конфликтов** при регистрации: два действия в одной области с одинаковым сочетанием — ошибка разработки.
3. **Таблица шорткатов в документации**, генерируемая из реестра, чтобы пользователь мог её увидеть, а разработчик — не забыть.
4. **Правило областей.** Глобальные сочетания (пробел — микрофон, палитра команд, Escape — закрытие) не перехватываются внутри пространства. Пространство пользуется только теми сочетаниями, которые свободны.

Глобальный слой командной консоли не переписывается: реестр добавляется как надстройка, а не замена.

---

## 7. F6.5 — Проход скринридером

По каждому пространству: пройти основной сценарий без мыши и с озвучкой, зафиксировать дефекты (порядок чтения, отсутствующие подписи, немые состояния) и исправить. Результат — отчёт в `docs/ux/spaces/` по формату из [`../backlog/remaining-spaces-audit.md`](../backlog/remaining-spaces-audit.md).

---

## 8. Definition of Done фронта

1. Фокус-кольцо существует в единственном определении и применено всеми примитивами; скрытого фокуса нет.
2. Окна, списки и иконочные кнопки имеют корректные роли и подписи.
3. Ключевые сценарии каждого пространства проходимы без мыши.
4. Реестр шорткатов существует, конфликты проверяются, таблица опубликована.
5. Проход скринридером выполнен минимум по трём пространствам с отчётами.

## 9. Метрики

| Показатель | До | После фронта |
|---|---|---|
| `aria-label` на 148 компонентов | 16 | покрытие всех иконочных кнопок |
| `role` | 16 | окна, списки, панели, вкладки |
| Ловушки фокуса | 0 | контракт окна (F2) + палитра команд |
| `tabindex` | 11 | по модели roving focus в списках |
| Пространства с клавиатурными сценариями | 0 (кроме запланированных Tasks) | все ключевые |
| Источник горячих клавиш | разрозненные обработчики | 1 реестр + проверка конфликтов |

---

## 10. Риски и их снятие

| Риск | Снятие |
|---|---|
| Новые сочетания конфликтуют с существующими | Реестр с проверкой конфликтов; пробел и Escape зарезервированы глобально |
| Клавиатурные сценарии мешают голосовому вводу | Голосовой тракт не трогается; сочетания, используемые микрофоном, исключены из регистрации пространств |
| Массовая правка ролей ломает вёрстку | Роли и подписи добавляются к существующим элементам без изменения структуры разметки |
| Работа дублируется из-за отставания F1/F2 | F6 стартует только после примитивов и диалогового контракта |
