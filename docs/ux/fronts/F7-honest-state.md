## 1. Зачем отдельный фронт

Разбор всех блоков показал второй класс дефектов, который не сводится к визуальной грамматике: интерфейс **утверждает то, чего нет**. Это не косметика — пользователь принимает решения по неверным данным и не понимает, что функция не работает.

Примеры (все подтверждены чтением кода):

| Что показывает интерфейс | Что происходит на самом деле |
|---|---|
| `RAM 45% · 6.6/8.0 GB` в статусной консоли | Объём считается как `memoryUsage * 0.08`, всего памяти — литерал `8.0` |
| Бейдж `READY` в расшифровке аудио | Статичная строка, не связанная ни с моделями, ни с занятостью |
| `ОНЛАЙН / АКТИВЕН` с пульсацией у 13 модулей | Литерал `status: 'active'` в статическом массиве |
| `OPT_BRIDGE v4.11` в оптическом канале | Выдуманное обозначение, поданное как версия подсистемы |
| Кнопка микрофона в чате пульсирует и «пишет» | Браузерный `webkitSpeechRecognition`; при его отсутствии — `setTimeout(…, 2000)` без записи |
| `Отменить` в тосте | Пустой колбэк `() => {}` — 10 вызовов из 45 |
| «ОТКАТ НА ЦП» с объяснением сбоя GPU | Реальный текст ошибки (`gpuWarningMessage`) получен и не показан |
| `A.R.C. Neural Core` как активная модель | Модель не выбрана; это подстановка по умолчанию |
| Разделы `Оркестратор`, `Агенты`, `Утилиты`, `Архитектура`, `Песочница` в навигации | Пространства не реализованы; переход ведёт в заглушку |

## 2. Правило фронта

1. **Индикатор обязан иметь источник данных.** Если данных нет — индикатор прямо говорит «нет данных» и не показывает вычисленную или подставную величину.
2. **Нереализованное действие не изображается как рабочее.** Либо честная формулировка «в разработке», либо действие отсутствует. Образец уже есть в проекте: `VisionTabView` («Распознавание не подключено (фаза 2)») и `FallbackTabView`.
3. **Ошибка показывается тем текстом, который получен от системы**, а не пересказом.
4. **Кнопка отмены существует только там, где отмена действительно возможна.**

## 4. Definition of Done

1. Ни один индикатор не показывает вычисленную или подставную величину: нет `memoryUsage * 0.08`, нет литерала `8.0`, нет `READY`, нет `A.R.C. Neural Core`.
2. Ни одна кнопка не выглядит рабочей там, где действия нет: тосты без пустых колбэков, карточки модулей без перехода в несуществующее пространство, микрофон без имитации записи.
3. Текст системной ошибки доходит до пользователя в том виде, в котором получен.
4. Проверка: ручной проход по семи сценариям (заголовок без метрик, расшифровка без модели, карта модулей, оптический канал, микрофон чата, тост памяти, чат без выбранной модели).

## 5. Риски

1. **F7.6** касается голосового контура: правки в `useVoice.ts` и `BottomBar.vue` требуют отдельного согласования; при отказе задача закрывается честным сообщением «голосовой ввод недоступен» без имитации.
2. **F7.4/F7.9** могут оголить неприятный факт: часть модулей действительно не реализована. Это цель фронта, но менять формулировки нужно вместе с `TAB_REGISTRY`, иначе пользователь увидит разные названия в трёх местах.
3. **F7.1** покажет реальный объём памяти, который может визуально отличаться от привычных цифр; это ожидаемое следствие и не является регрессией.
