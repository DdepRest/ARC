## 1. Задача фронта

Whitelist `scripts/check-file-sizes.js` закрыт для нового кода: превышения разрешены только легаси-файлам, существовавшим до 24.08.2026. При этом **вне whitelist** уже 13 файлов в полосе 350–396 строк. Это значит: следующая функция в любом из них упирается не в задачу, а в рефакторинг, а попытка уложиться в лимит приводит к выкидыванию логики куда угодно.

Целевое состояние: **ни один рабочий файл не подходит к лимиту ближе, чем на 70 строк** — то есть максимум около 330, с обязательным планом разнесения после 300.

## 3. Правила разнесения

Разнесение — операция с риском регрессий, поэтому правила жёсткие:

1. **Разделяются только представление и чистые функции.** Состояние остаётся там, где было: перенос состояния между компонентами — это уже переработка, а не разнесение.
2. **Один шаг — один файл.** Не «разнесу все 13», а один файл с проверкой и ручным сценарием.
3. **Целевой размер после разнесения — ниже 300 строк**, а не «чуть меньше 400»: иначе через две функции проблема вернётся.
4. **Данные — в данные.** Реестры (модули, виджеты, модели) уходят в отдельные файлы данных, где действует лимит 800 строк. Это самый безопасный вид разнесения.
5. **Ничего не меняется по существу.** Если при разнесении обнаруживается дефект логики — он фиксируется отдельной задачей и не «попутно лечится».
6. **Приоритет по потребности.** Первым разносится файл, в котором планируется ближайшая работа; список из раздела 2 — карта, а не очередь.

## 4. Видимость давления (дополнение к инфраструктуре)

Проверка размеров сейчас сообщает только о превышении. Предлагается добавить в `scripts/check-file-sizes.js` режим отчёта: команда печатает **топ-10 самых крупных файлов вне whitelist** с их долей от лимита.

Зачем: давление на лимит становится видимым каждый день, и разнесение планируется заранее, а не в момент, когда сборка уже упала. Отчёт ничего не ломает — только показывает, поэтому его можно включить сразу и использовать как часть ревью.

---

## 5. Definition of Done фронта

1. Ни одного файла вне whitelist в полосе 350–396 строк.
2. Отчёт по топ-10 доступен как команда.
3. Каждое разнесение проверено: `npm run lint`, `npm run test`, `npm run build` (включая проверку размеров), ручной сценарий соответствующего экрана.
4. Поведение экранов не изменилось — разнесение не является переработкой.
