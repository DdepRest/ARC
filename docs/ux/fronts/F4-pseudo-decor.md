# F4 — Псевдо-декор: эмодзи, фейковые данные, мёртвый код

**Фронт:** четвёртый (можно выполнять параллельно с F1 и F2, если не пересекаться по файлам).
**Основание:** [`../02-global-audit.md`](../02-global-audit.md) (дефекты C10, C12), [`../01-vision.md`](../01-vision.md) (принцип «профессионализм — в точности»).

---

## 1. Задача фронта

Убрать из интерфейса всё, что имитирует смысл: случайные числа, выдаваемые за телеметрию, декоративные символы в служебном слое и код, которого нет в живом интерфейсе. Это самый быстрый фронт с точки зрения трудозатрат и самый значимый с точки зрения доверия к интерфейсу.

---

## 2. F4.1 — Фейковая телеметрия (приоритет)

`StatusOverlay.vue` содержит генератор случайного hex-числа: значение `0x0000` при инициализации заменяется случайным числом и показывается как технический идентификатор. Никакой информации это не несёт, но выглядит как данные.

Дополнительно выяснено: компонент используется **только** внутри `layouts/FocusMode.vue`, который сам не импортируется нигде. То есть поддельная телеметрия не просто бесполезна — она мертва в двойном смысле.

Решение: удалить `FocusMode.vue` и `StatusOverlay.vue` вместе. Если в будущем понадобится полноэкранный режим фокуса, он проектируется по контракту пространства из видения, а не восстанавливается из мёртвого кода.

**Проверка перед удалением:** поиск ссылок по имени, отсутствие в чанках динамической загрузки, успешная сборка.

---

## 3. F4.2 — Эмодзи из служебного слоя

В `.vue`-файлах 103 эмодзи. Наибольшая концентрация — там, где эмодзи подменяют типографику и иконки:

| Файл | Эмодзи | Что заменяется |
|---|---|---|
| `TaskConsole.vue` | 18 | `🔥`/`⚡`/`📋` в приоритетах, `📅` в датах, `🏷️` в тегах, `☀️` в «Моём дне» |
| `ObjectiveDetailsWorkspace.vue` | 11 | `✓`/`✦` в статусах и метках |
| `PerformanceSettings.vue` | 8 | `✓`, `⚠` в результатах тестов |
| `FpsOverlay.vue` | 5 | Символы в диагностике |
| `ProviderModelCatalog.vue` | 5 | `✓`, `+` в выборе моделей |
| `TaskItemMetadata.vue` | 5 | Приоритеты и статусы |
| `RecurrenceModal.vue` | 4 | `♾️`, `🔢`, `📅` в правилах повторения |
| `BuiltinModelCard.vue` | 4 | Статусы загрузки |
| остальные | ~43 | Точечно по пространствам |

**Политика замены:**

1. **Приоритеты** (`🔥`/`⚡`/`📋`) → текстовые метки Машинного слоя: `P1`, `P2`, `P3` с цветовой ролью. В интерфейсе задач приоритет уже показывается как `P2` — эмодзи дублирует эту информацию и размывает Машинный слой.
2. **Смысловые маркеры** (`♾️` бесконечно, `🔢` до N раз) → короткие текстовые формы (`бесконечно`, `до 3 раз`) либо иконка `lucide`.
3. **Интерфейсные значки** (`✓`, `+`, `▾`, `⚙`) → иконки `lucide-vue-next`; библиотека уже используется в проекте повсеместно.
4. **Украшения в заголовках** (`✦`) → убираются либо заменяются акцентным маркером статуса.
5. **Пользовательское содержание** (например, текст задачи, который написал пользователь) — не трогается: эмодзи там законны.

**Правило:** эмодзи запрещены в хроме интерфейса, допустимы в пользовательских данных. Проверяется защёлкой из F1.7.

## 4. F4.3 — Мёртвый код

Без единого импорта:

| Файл | Заметка |
|---|---|
| `components/ModelHub.vue` | Дублирует раздел «Менеджер моделей» |
| `components/ui/ArcBadge.vue` | Примитив без использования (решение о судьбе — в F1) |
| `components/ui/GlassPanel.vue` | Примитив без использования (панель становится композицией) |
| `components/ui/TabLoadingSkeleton.vue` | Заменён другими состояниями загрузки |
| `features/chat/components/ChatMemoryStream.vue` | Не подключён |
| `features/home/components/HomeDashboard.vue` | Пространство «Главная» не используется: интерфейс строится вокруг Core и пространств |
| `features/tasks/components/AIRecommendationBox.vue` | Заменён рейлом контекста |
| `features/tasks/components/TaskContextPanel.vue` | Заменён `TaskContextRail` |
| `features/tasks/components/TaskSidebar.vue` | Заменён рейлом |
| `layouts/FocusMode.vue` | Удаляется вместе с `StatusOverlay.vue` (см. F4.1) |

Плюс недостижимые в настройках: `HubSettings.vue` (импортируется, никогда не рендерится) и `SettingsSection.vue` (ноль ссылок).

Эти два файла удаляются в **итерации A плана Settings** ([`../04-tasks-settings.md`](../04-tasks-settings.md)) — по правилу стыковки из [`../03-roadmap.md`](../03-roadmap.md): если файл входит и в фронт, и в план Tasks/Settings, приоритет у плана. В этом фронте они остаются только счётной строкой, двойной работы нет.

**Процедура удаления (обязательна для каждого файла):**

1. Поиск по имени файла и по имени компонента во всём `src` (шаблоны, скрипты, динамические импорты по маске).
2. Проверка, что файл не упоминается в документации как действующий (если упоминается — сначала поправить документ).
3. Удаление, затем `npm run lint && npm run test && npm run build`.

Ограничение метода: подсчёт по вхождению имени может давать ложные срабатывания при одноимённых строках, поэтому шаг 1 выполняется вручную, а не скриптом.

## 5. F4.4 — Правило против псевдо-декора

В `docs/current-state.md` и в контракте пространства (видение, пункт 4) фиксируется:

1. Любое число на экране имеет источник в данных. Декоративные идентификаторы, случайные значения и «примерные» графики запрещены.
2. Готовность функции обозначается честно: либо данные, либо «модуль в разработке».
3. Эмодзи не используются в служебных слоях.
4. Проверяется защёлкой дисциплины: счётчик эмодзи и число «пустых» компонентов с фиктивными данными не могут расти.

## 6. Definition of Done фронта

1. `StatusOverlay.vue` и `FocusMode.vue` удалены; в проекте нет генераторов случайных «телеметрий».
2. Эмодзи в хроме интерфейса — 0; замена выполнена иконками или текстом Машинного слоя.
3. 12 мёртвых сущностей удалены, каждая — с процедурой проверки и успешной сборкой.
4. Правило против псевдо-декора зафиксировано в документации и в защёлке.

## 8. Риски и их снятие

| Риск | Снятие |
|---|---|
| Эмодзи несут различимость (приоритеты, статусы) | Замена на текстовые метки и цветовые роли; проверить, что задача с приоритетом `P1` визуально отличается от `P3` |
