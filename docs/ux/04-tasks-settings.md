## 1. Принципы и ограничения

1. **Дефект → структура → тишина.** Сначала чинятся подтверждённые функциональные поломки, затем разгружается структура, и только потом выравнивается визуальный вес. Изменений «ради обновления вида» нет.
2. **Экран за экраном.** Одна итерация — одно пространство (или один связный слой), максимум 3–5 связанных файлов логики.
3. **Layout Specification до кода.** Перед правками формулируется текстовая структура слоя; она зафиксирована ниже в каждой итерации.
4. **A.R.C. Identity Check после каждой итерации.** Стало ли удобнее; стало ли спокойнее; сохранился ли характер A.R.C.; не стал ли экран похож на обычный SaaS (при ответе «да» на последнее — откат решения).
5. **Лимиты размеров** (`scripts/check-file-sizes.js`): логика — 400 строк, данные — до 800, типы — до 600. Скрипт запускается внутри `npm run build` и валит сборку при превышении. Файлы данных/легаси в `IGNORE_FILES`: `tasks.store.ts`, `settings.store.ts`, `useSettingsNav.ts`, `RecurrenceModal.vue`, `ModelManagerSection.vue`, `STTSection.vue`, `TTSSection.vue`. **Новый код обязан соответствовать лимитам строго** — добавление новых файлов в whitelist запрещено (whitelist только для легаси до 24.08.2026).
6. **Критичные ориентиры по размеру:** `TaskConsole.vue` = 375 строк (потолок 400) — поэтому Итерация C1 сначала выносит дубли, и только потом C2 меняет разметку. `TaskItem.vue` = 186, `SettingsMenu.vue` = 157, `TaskContextRail.vue` = 154 — запас есть.
7. **Зона «НЕ ТРОГАТЬ» не затрагивается:** стек 3D Reactor, `useVoice.ts`, `built-in-llm.service.ts`, `useMacroEditor.ts`, `ObjectiveEngine.ts`, `BottomBar.vue`, VoiceFSM, а также Pinia-сторы — кроме единственной разрешённой точечной правки 1 строки в `tasks.store.ts` (см. Итерацию C1, п. 2).
8. **Новых IPC-методов нет** — заглушки в `mock-database.ts` не требуются.

## 4. Итерации

### Итерация A — Settings: целостность навигации

**Layout Specification.** Сайдбар строится по схеме `Категория → Секция`, где **каждая секция соответствует реальному видимому блоку страницы**, а её подпись совпадает с заголовком этого блока. CORE: «Быстрые параметры» · «Интерфейс и тема» · «Панели и виджеты» · «Навигация и вкладки» · «Система и ресурсы» · «Интеграции». SYSTEM: «Производительность» · «Диагностика и отчёты». Контент страниц не перестраивается — выравнивается только карта навигации.

1. `useSettingsNav.ts` — канонизировать id секций по фактически существующим анкорам (`section-quick`, `section-appearance`, `section-widgets`, `section-navigation`, `section-system`, `section-integrations`), расширить `keywords` фактическими подписями строк, добавить в `scrollToSectionId`/`handleViewScroll` диагностическое предупреждение при отсутствии анкора — защита от повторного дрейфа.
2. `PerformanceSettings.vue` — анкор `section-monitoring` → `section-performance` (единый канон id из меню; 4 строки внутри файла).
3. `SettingsMenu.vue` — убрать неиспользуемые функции и `toggleSidebar`/`isSidebarCollapsed`, заменить англоязычный бейдж `MATCH` локализованным счётчиком совпадений.
4. `SettingsPanel.vue` — убрать импорт неиспользуемого `HubSettings` и локальный дублирующий баннер сохранения (остаётся глобальный `SyncToast` с Undo).
5. `useSettingsNav.test.ts` — обновить ожидания и добавить регресс-тест: для каждого `id` из `SETTINGS_MENU` в соответствующем `.vue` существует `id="<id>"` (тест читает файлы как текст). Это закрывает S1–S3 от повторения.
6. Удалить недостижимые `HubSettings.vue` и `SettingsSection.vue` — только после контрольного поиска ссылок.

**Definition of Done.** Все пункты меню кликабельны и ведут к своему блоку; активный пункт всегда соответствует видимой области при скролле; подписи меню и заголовки страниц совпадают; новый тест проходит.
**Риски.** Смена id ломает сохранённый в `localStorage` ключ активной секции — `SettingsPanel.vue` уже умеет откатываться на первую секцию, поведение проверить вручную.

### Итерация B — Settings: честные контролы и цивилизованный сброс

**Layout Specification.** Раздел «Интерфейс и тема» содержит только реально работающие контролы. «Быстрые параметры» — это быстрые действия, а не витрина чужих настроек. Сброс — не кнопка в футере, а модальное действие со явным списком последствий.

1. `global.css` — реализовать `body.dark-protocol` реальными оверрайдами контраста (текст, границы, поверхности интерфейса). **Запрещено** трогать `--core-glow` и `--accent-*`: подсветка и поведение реактора неприкосновенны.
2. `AppearanceSection.vue` — «Тёмная тема» переименовывается в «Повышенный контраст интерфейса» с описанием фактического эффекта. Ключ хранения `darkMode` сохраняется ради обратной совместимости уже сохранённых профилей.
3. `QuickCoreSection.vue` — «Громкость голоса» становится настоящим `ArcSlider` на `store.voiceVolume`. Стор остаётся единственным источником данных, второй копии значения не появляется; настройка перестаёт быть витриной.
4. Новый `SettingsResetModal.vue` (< 400 строк) — стекло `bg-[#070709]/65 backdrop-blur-2xl`, бэкдроп `bg-black/30 backdrop-blur-sm`, явный перечень того, что будет сброшено.
5. `SettingsMenu.vue` — `confirm()` удаляется, кнопка открывает модалку; сама кнопка становится визуально тише (приглушённая, не акцентная).

**Definition of Done.** Тумблер контраста заметно меняет читаемость интерфейса и не влияет на реактор; громкость меняется из быстрых параметров и синхронна с разделом «Голос»; сброс требует подтверждения через модалку Arc Glassmorphism.
**Риски.** Контрастные оверрайды не должны ломать уже согласованные экраны — проверять на всех пространствах, а не только в настройках.

### Итерация C1 — Tasks: снятие дублей и битых классов

**Layout Specification.** Строка задачи — плотная двухстрочная единица: слева вертикальный статус-маркер, затем заголовок (Human Layer) и строка метаданных (Machine Layer). Выбранное состояние передаётся фоном, а не рамкой.

1. `TaskConsole.vue` — импорт хелперов из `../utils/task-console.util` вместо локальных дублей. Итог: ~305 строк, появляется запас до лимита 400.
2. `tasks.store.ts` — разрешённая точечная правка **1 строки**: `getDueDateClass` возвращает валидные классы.
3. `RecurrenceModal.vue` — 4 битых класса (`:17, 42, 46, 90`).
4. `TaskItem.vue` — плотность (`py-2`), метаданные одной строкой, выделение выбранной задачи фоном `bg-white/[0.05]` с сохранением левого акцентного маркера (закрывает T6).
5. `TaskList.vue` — вертикальный ритм списка.

**Definition of Done.** Акцентные заливки и рамки фактически применяются (проверка по собранному CSS); строка задачи стала плотнее без потери читаемости; выделение читается фоном.
**Риски.** Правка стора — ровно одна строка и только в разрешённом месте; поведение `getDueDateClass` не меняется, меняется только синтаксис классов.

### Итерация C2 — Tasks: консоль в один уровень и группа «Готово (N)»

**Layout Specification.** Верхняя панель пространства — одна строка: `Очередь задач • N/M` + сегментированный переключатель пяти режимов + «Аналитика» + кольцо выполнения. Ниже — консоль из двух строк: строка ввода (с «Параметрами») и строка поиска/сортировки. Фильтры — отдельная тихая полоса пилюль. Список: активные задачи сверху, ниже сворачиваемая группа «Готово (N)», свёрнутая по умолчанию.

1. `TaskHeaderBar.vue` — принимает переключатель режимов как сегментированный контроль (иконка + подпись, активное состояние — фирменный A.R.C. RED).
2. `TaskConsole.vue` — освобождается от яруса режимов; «Шаблоны» переезжают в «Параметры».
3. `SearchFiltersPanel.vue` — разделяется на компактную строку поиска/сортировки и полосу фильтров.
4. Новый `TaskCompletedGroup.vue` (< 400 строк) — disclosure «Готово (N)» с сохранением существующих анимаций списка.
5. `TaskList.vue` — собирает активные задачи и группу готовых.

**Definition of Done.** На первый экран попадает существенно больше активных задач; завершённые не мешают сканировать активные; все пять режимов работают из новой позиции переключателя.
**Риски.** `TaskConsole.vue` после C1 имеет запас ~95 строк — итог C2 не должен вернуть файл к потолку 400.

### Итерация D — Tasks: рейл без card-in-card и клавиатурный слой

**Layout Specification.** Рейл — **одна** поверхность. Внутри — плоские группы с заголовками Машинного слоя и разделителями `border-white/5`, без вложенных карточек, рамок и теней. Метрика живёт в одном месте: счётчик и кольцо — в шапке; в рейле остаются действие и контекст выбранной задачи.

1. `TaskContextRail.vue` — снять вложенную карточку, перейти на плоские группы; полный инспектор задачи (метаданные, шаги, ссылки, быстрые действия) сохраняется без потерь.
2. `TaskTelemetry.vue` — убрать дубли с шапкой («СИСТЕМА/Выполнено», второе «Сегодня», кнопку «Аналитика»); «ПРОБЛЕМЫ (N)» становится кликабельным переходом к просроченным задачам; «Экспорт» остаётся единственным действием уровня рейла.
3. Новый `useTaskKeyboardNav.ts` (< 400 строк): ↑/↓ — навигация, Enter — завершить, E — переименовать, Del — удалить (с существующим Undo-тостом), `/` — фокус поиска, `1…5` — режимы просмотра, Esc — снять выбор. Шорткаты строго ограничены активной вкладкой Tasks; пробел не перехватывается (он принадлежит микрофону), Esc не конфликтует с закрытием проекции.
4. `TaskItem.vue` — фокус-кольцо и `data-task-id` для roving focus.
5. `TaskList.vue` — контейнер активного индекса.

**Definition of Done.** Рейл читается как единая панель без визуальных «матрешек»; одинаковая метрика не показывается дважды; список полностью управляется с клавиатуры, глобальные шорткаты не сломаны.
**Риски.** Конфликт с шорткатами `useCommandCenter` (Space, Esc, ⌘K) — обязательная проверка после реализации.

### Итерация E — Shell: настоящее стекло проекции (отдельный шаг)

**Layout Specification.** Рабочее пространство — парящее стекло: сквозь него видны реактор и космический фон. Кнопка закрытия перестаёт быть самым громким элементом заголовка.

1. `HolographicProjectionPanel.vue` — глухой фон `!bg-black/85 backdrop-blur-3xl` (:10) заменяется стеклом `bg-[#070709]/65 backdrop-blur-2xl` (Visual Constitution прямо запрещает глухой чёрный для модальных и рабочих поверхностей); кнопка закрытия переводится в ghost-стиль (`border-transparent`, фон только при наведении) — Esc уже закрывает проекцию; бейдж `v5.0` (:23) привязывается к реальному источнику версии либо удаляется (никаких выдуманных надписей).
2. Проверка всех десяти пространств: Чат, Память, Команды, Цели, Файлы, Транскрибация, Модули, Vision, Tasks, Settings.

**Definition of Done.** Реактор и фон читаются сквозь рабочее пространство, при этом текст и контролы сохраняют контраст; ни один экран не потерял читаемость.
**Риски.** Файл общий для всех пространств — итерация идёт последней и отдельно, с визуальной проверкой каждой вкладки.

## 5. Протокол проверок (после каждой итерации)

1. `npm run lint` — TypeScript без ошибок.
2. `npm run test` — vitest; целевые тесты: `useSettingsNav.test.ts` и новый тест соответствия анкоров.
3. `npm run check-sizes` — лимиты размеров; для новых файлов строго < 400 строк.
4. `npm run build` — полная сборка (включает проверку размеров).
5. Ручная визуальная проверка: запуск через `arc.bat`, просмотр последнего лога через `open_latest_log.bat`.
6. A.R.C. Identity Check по четырём вопросам Протокола.

## 6. Риски и ограничения (сводно)

| Риск | Митигация |
|---|---|
| `HolographicProjectionPanel.vue` общий для десяти пространств | Итерация E идёт последней, отдельно, с проверкой каждой вкладки |
| Смена id секций настроек ломает сохранённый `localStorage`-ключ | Откат на первую секцию уже реализован в `SettingsPanel.vue` + новый регресс-тест анкоров |
| Удаление `HubSettings.vue` / `SettingsSection.vue` | Перед удалением — контрольный поиск ссылок (сейчас: у `HubSettings` только импорт, у `SettingsSection` ноль ссылок) |
| Клавиатурный слой ломает глобальные шорткаты | Scope только внутри активной вкладки Tasks; пробел и Esc не перехватываются |
| Правка Pinia-стора | Ровно 1 строка в `tasks.store.ts`, разрешена отдельно; других правок сторов нет |
| `TaskConsole.vue` у потолка 400 строк | Дубли выносятся в C1 до структурных изменений C2 |
