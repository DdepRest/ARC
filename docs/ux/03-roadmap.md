## 1. Общие правила работ

1. **Лимиты размеров:** логика — 400 строк, данные — до 800, типы — до 600. Новые файлы в whitelist `scripts/check-file-sizes.js` **не добавляются** (whitelist только для легаси до 24.08.2026). Правки в файлах из полосы 350–396 строк начинаются с выноса логики.
2. **Зона «НЕ ТРОГАТЬ»:** стек 3D Reactor, `useVoice.ts`, `built-in-llm.service.ts`, `useMacroEditor.ts`, `ObjectiveEngine.ts`, `BottomBar.vue`, VoiceFSM, Pinia-сторы (кроме уже разрешённой 1 строки в `tasks.store.ts`). Все работы этого плана — вне этих файлов.
3. **Проверки после каждой итерации:** `npm run lint`, `npm run test`, `npm run check-sizes`, `npm run build`, ручная проверка через `arc.bat` + `open_latest_log.bat`.
4. **A.R.C. Identity Check** по четырём вопросам Протокола; при уклоне «стало похоже на обычный SaaS» — откат.
5. **Новые IPC-методы не создаются** — заглушки в `mock-database.ts` не требуются.
6. **Документирование:** после каждой завершённой итерации обновляется `docs/current-state.md` (блок с датой и составом изменений).

## 11. Следующие шаги по приоритету

1. **F1.1–F1.5** — токены и служебный слой (одна-две итерации, минимальный риск, максимальный эффект на всю дальнейшую работу).
2. **F1.6–F1.9** — примитивы, защёлка дисциплины, галерея примитивов, план миграции.
3. **Параллельно:** итерации A и B плана Tasks/Settings (навигация настроек и честные контролы) — они не конфликтуют с F1.
4. **F2.3** — отдельным приоритетом как диалог безопасности.
5. **F7** — правдивость состояния: быстрые точечные исправления с заметным эффектом (показной RAM, `READY`, статусы модулей, пустые отмены).
6. Далее: F4 (быстрые победы), F2 (полный оконный слой), F3, F5, F6.
