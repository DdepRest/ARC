# Инструкция по профилированию производительности ARC

Для правильного выявления причин микрофризов и просадок FPS (Frame Per Second) необходимо соблюдать методику снятия трейсов. Неправильный метод может исказить результаты, так как сам профайлер накладывает оверхед на CPU/GPU.

## 1. Профилирование FPS и микрофризов (Rendering & GPU)

**ЦЕЛЬ:** Найти причину просадок кадров, задержек рендеринга Three.js или конфликтов за ресурсы GPU (context switching).

**ПРАВИЛО:** При поиске проблем с FPS **ОТКЛЮЧАЙТЕ** CPU Profiler! Сам факт записи стеков вызовов JS-движка сильно снижает FPS и создает фантомные задержки, маскируя реальную проблему.

**Алгоритм снятия трейса FPS:**
1. Откройте Chrome DevTools (F12) -> вкладка **Performance**.
2. Убедитесь, что галочка **"Disable JavaScript samples"** установлена (это отключит глубокий CPU profiling).
3. Убедитесь, что галочка "Screenshots" включена (полезно для понимания визуального контекста).
4. Убедитесь, что галочка "Enable advanced paint instrumentation" отключена, если вы не профилируете конкретный CSS Paint.
5. Нажмите "Record".
6. Воспроизведите сценарий, вызывающий микрофризы (например, переключение на тяжелую игру вроде BeamNG.drive с активным ARC на фоне).
7. Нажмите "Stop".
8. Сохраните трейс: правый клик -> **"Save profile..."** -> назовите файл `fps_trace_[date].json`.

## 2. Профилирование Audio / STT (CPU & Workers)

**ЦЕЛЬ:** Найти причину зависаний распознавания речи, долгих пауз (AudioBuffer processing) или перегрузок Web Worker (ONNX STT).

**ПРАВИЛО:** При поиске проблем с вычислениями (JS Execution) **ВКЛЮЧАЙТЕ** CPU Profiler. Нам не важен FPS в данный момент, важен call stack.

**Алгоритм снятия трейса Audio/STT:**
1. Откройте Chrome DevTools (F12) -> вкладка **Performance**.
2. Убедитесь, что галочка **"Disable JavaScript samples"** СНЯТА (нам нужны стек-трейсы).
3. Нажмите "Record".
4. Произнесите команду в микрофон или активируйте обработку тяжелого аудио-файла.
5. Дождитесь завершения обработки (или момента зависания).
6. Нажмите "Stop".
7. Сохраните трейс: правый клик -> **"Save profile..."** -> назовите файл `audio_trace_[date].json`.

## 3. Мониторинг через встроенные инструменты ARC

В ARC встроены собственные debug-оверлеи, которые полезны для быстрого мониторинга без открытия DevTools.
> **Внимание:** Debug-компоненты доступны только в development сборках (`import.meta.env.DEV`) для предотвращения overhead'а в production.

*   **FPS Overlay:** Показывает текущий FPS, мониторинг кадров и информацию о GPU. Включается в `Настройки -> Производительность`.
*   **Performance Profiler:** Детальный график FPS с историей.

## 4. Чеклист после оптимизации

*   Сравнить FPS в игре (например, BeamNG.drive) "ДО" и "ПОСЛЕ" оптимизаций.
*   Убедиться, что при потере фокуса (`isWindowFocused === false`) частота кадров снижается согласно настройкам `ecoStore`, и нагрузка на GPU падает.
*   Убедиться, что `requestAnimationFrame` или `setInterval` в фоновых виджетах (например, MusicCapsuleWidget) не провоцируют постоянные обновления DOM при бездействии.
