# Глубокий анализ производительности и оптимизации (FPS Fix Spec v0.3-Analysis)

Данный документ представляет собой результат профилирования текущей архитектуры приложения и выделяет векторы для дальнейшей стабилизации кадровой частоты (FPS) без ущерба для визуальной составляющей (Without Destroying Visuals).

## 1. Композитный узкий сустав (Compositor Bottleneck)
В текущей архитектуре одновременно обновляются три независимых слоя, что создает избыточную нагрузку на Chromium Compositor:
1. **WebGL Контекст (`ReactorCore.vue`)** - Отрисовка 3D-сцены с тяжелым пост-процессингом (UnrealBloomPass).
2. **2D Canvas (`SpaceBackground.vue`)** - Отрисовка летящих частиц данных на фоне.
3. **2D Canvas (`FpsOverlay.vue`)** - Отрисовка графиков телеметрии поверх всего.
4. **CSS Animations (`SpaceBackground.vue`)** - Вращающиеся орбитали (анимации `spin_120s`, `spin_240s`).

**Анализ:**
Перекрытие множества прозрачных контекстов, обновляющихся в одном `requestAnimationFrame`, ломает возможности аппаратного тайлинга (Hardware Tiling) и заставляет GPU постоянно пересчитывать смешивание слоев (Alpha Blending).

**Предлагаемые решения:**
- **Throttle Background:** Ограничить частоту обновления 2D Canvas в `SpaceBackground.vue` (например, аппаратно привязать к 30 FPS).
- **Merge Contexts (Сложно):** Перенести партиклы из `SpaceBackground.vue` в сцену Three.js (`ReactorCore.vue`), чтобы всё рендерилось в один проход WebGL.
- **CSS `will-change: transform`:** Добавить на слои с CSS-анимациями вынос в GPU-текстуры, чтобы не вызывать Paint основного DOM-дерева.

## 2. Разрешение рендеринга (Fillrate Limits)
Устройства с Retina/4K дисплеями имеют `window.devicePixelRatio` равный 2 или 3. Рендеринг `UnrealBloomPass` в таком разрешении уничтожает производительность интегрированных видеокарт.

**Анализ:**
В `ReactorCore.vue` сейчас используется ограничение:
`Math.min(window.devicePixelRatio, pixelRatioMap[settingsStore.graphicsQuality]) * scale`
Где `High` = 1.5, `Medium` = 1.25, `Low` = 1.0. 
Это *уже* отличное решение. Однако сам `UnrealBloomPass` делает несколько проходов.

**Предлагаемые решения:**
- **Dynamic Bloom Resolution:** При деградации качества в `LOD Auto-Degrade` мы можем не только менять базовое качество, но и динамически пересоздавать `UnrealBloomPass` с еще меньшим разрешением.
- **Selective Bloom:** Рендерить Bloom только для определенных слоев, но это потребует переписывания пайплайна композитора.

## 3. Управление памятью GPU (Memory Leaks)
**Анализ:**
В функции `onUnmounted` компонента `ReactorCore.vue` вызывается `renderer.dispose()`. Однако, в Three.js это не очищает VRAM от загруженных геометрий (Geometries) и материалов (Materials). При переключении страниц (если компонент демонтируется и монтируется заново), это приведет к утечке памяти.

**Предлагаемые решения:**
- Написать утилиту для рекурсивного обхода сцены (`scene.traverse`) в `onUnmounted`, которая вызывает `dispose()` у каждого `Geometry`, `Material` и `Texture`.

## 4. Оптимизация VDOM / Vue Reactivity
**Анализ:**
График `FpsOverlay` и счетчики обновляют реактивные переменные (ref) несколько раз в секунду. В Vue 3 это вызывает процесс diff-инга виртуального DOM. Массив `sessionHistory` пушится каждую секунду.

**Предлагаемые решения:**
- Обернуть массивы данных телеметрии (например, `sessionHistory`) в `shallowRef` вместо обычного `ref`, чтобы Vue не вешал Proxy-геттеры/сеттеры на каждый объект истории.

## 5. Выводы (Actionable Items)
С учетом требования "не уничтожая визуал", наиболее безопасными и эффективными шагами прямо сейчас являются:
1. Внедрить рекурсивную очистку GPU-памяти в `ReactorCore.vue`.
2. Перевести массивы истории в `FpsOverlay` на `shallowRef` (снижение оверхеда JS).
3. Ограничить FPS фонового канваса в `SpaceBackground.vue` до 30 кадров в секунду (это сохранит динамику, но уберет огромную часть нагрузки на композитор).
