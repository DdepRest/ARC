# Руководство по участию в разработке A.R.C. (Contributing Guide)

Благодарим за интерес к развитию проекта **A.R.C. (Autonomous Reactor Core)**!

A.R.C. — это высокопроизводительный локальный автономный настольный ассистент, построенный вокруг живого 3D-реактора. Чтобы проект оставался стабильным, быстрым и верным своей визуальной ДНК, все участники разработки следуют установленным архитектурным правилам.

---

## 🛠 Подготовка окружения для разработки

### Требования
- **ОС**: Windows 10 / 11 (64-bit)
- **Node.js**: `20.x LTS` (npm 10+)
- **Python**: `3.10+` (рекомендуется для Silero TTS и локальных утилит)
- **Аппаратные требования**: 4+ ядра CPU с AVX2, от 8 ГБ RAM

### Быстрый старт
1. **Клонирование репозитория**:
   ```bash
   git clone https://github.com/your-username/a.r.c.git
   cd a.r.c
   ```

2. **Установка зависимостей Node.js**:
   ```bash
   npm ci
   ```

3. **Синтез речи (Silero TTS)**:
   При первом запуске скрипт автоматической настройки подготовит локальное виртуальное окружение:
   ```cmd
   setup_silero.bat
   ```
   Или вручную:
   ```powershell
   python -m venv test_env
   .\test_env\Scripts\Activate.ps1
   pip install -r requirements-silero.txt
   ```

4. **Запуск в режиме разработки**:
   ```bash
   # Запуск интерфейса и Electron
   npm run electron:dev
   ```

## 🏛 Архитектурные принципы и ограничения

### 1. Защищённая зона ядра (Core Protected Areas)
3D Reactor является визуальным и архитектурным ядром A.R.C. Категорически запрещено упрощать, переводить в 2D/SVG или удалять:
- `src/renderer/components/reactor/**`
- `ReactorCore.vue`
- `useReactor3D.ts`
- Трёхмерные шейдеры, геометрию, материалы и систему частиц.

Также защищены от нецелевого рефакторинга:
- `src/renderer/composables/useVoice.ts` и `VoiceFSM`
- `src/main/services/built-in-llm.service.ts`
- `src/main/services/objective/ObjectiveEngine.ts`
- `src/renderer/components/panels/BottomBar.vue`

### 2. Лимиты на размер файлов (Modularity Limit)
- Компоненты Vue, сервисы, композаблы и утилиты: **≤ 400 строк кода**.
- Файлы конфигурации, словари, реестры и сторы данных: **≤ 800 строк кода**.
- Проверка лимитов выполняется автоматически командой `npm run check-sizes`.

### 3. Визуальная конституция (A.R.C. Design System)
В A.R.C. запрещены произвольные hex/rgb цвета в компонентах:
- **Поверхности**: задаются строго через непрозрачную лестницу токенов `var(--arc-frame)`, `var(--arc-plane)`, `var(--arc-block)`, `var(--arc-rail)` из `tokens.css`.
- **Акценты**: задаются строго через `var(--accent)` и `var(--accent-rgb)`. Литеральные Tailwind-классы (`bg-red-500`, `text-red-500`) запрещены.
- **Правило стекла и мата**: стекло и блюр живут только над статикой и на кромках; над 3D-канвасом и под блоками текста используется глубокий мат.

Проверка соблюдения правил дизайна выполняется скриптом `npm run check-visual-constitution`.

## 🧪 Обязательные проверки перед коммитом (CI Gate)

Перед созданием коммита и отправкой Pull Request обязательно выполните:

```bash
# Комплексный гейт проверок:
npm run gate
```

Или по отдельности:
1. `npm run lint` — проверка строгой типизации TypeScript (`tsc --noEmit`).
2. `npm run check-sizes` — контроль лимитов строк кода.
3. `npm run check-visual-constitution` — аудит конституции токенов интерфейса.
4. `npm test` — прогон набора модульных тестов Vitest.

---

## 🚀 Процесс создания Pull Request

1. Создайте отдельную ветку для задачи: `git checkout -b feat/my-new-feature` или `fix/issue-description`.
2. Вносите минимально необходимые и сфокусированные изменения.
3. Убедитесь, что `npm run gate` завершается без единой ошибки.
4. Создайте Pull Request в ветку `main`, подробно заполнив пункты чеклиста в шаблоне PR.
