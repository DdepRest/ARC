# Политика безопасности A.R.C. (Security Policy)

## 1. Модель угроз (Threat Model)

A.R.C. (Autonomous Reactor Core) — локальное настольное приложение с расширенными правами: доступом к файловой системе, выполнением shell-команд, записью аудиопотока и сетевым взаимодействием с LLM-провайдерами.

### Основные векторы атак:
1. **Prompt Injection**: Манипуляция инструкциями модели через пользовательский ввод или внешние контексты с попыткой запуска деструктивных команд.
2. **Вредоносные макросы / сценарии**: Попытка выполнения произвольного шелл-кода или удаление системных файлов через автоматизацию.
3. **Кража или утечка API-ключей**: Доступ к секретам провайдеров (OpenAI, Anthropic, Gemini, Groq) через чтение конфигурационных файлов или логи.
4. **XSS / Инъекции в UI**: Внедрение вредоносных тегов через Markdown или форматированные ответы ассистента в Renderer-процесс.

## 2. Компенсирующие меры безопасности (Compensating Controls)

| Вектор угрозы | Защитный механизм | Реализация |
|---|---|---|
| Несанкционированный Shell | **Approval Flow** | Обязательное явное подтверждение пользователем в UI любых команд `SHELL_RUN` и деструктивных операций (`ShellApprovalService`) |
| Path Traversal / Взлом FS | **SandboxedFS & Path Containment** | Валидация канонических путей (`isPathAllowed`, `resolveMacroFilePath`, `isSafeCacheFilePath`), блокировка `..`, симлинков и выхода за пределы разрешённых директорий |
| XSS / Внедрение скриптов | **Dual-layer CSP** | Запрет `'unsafe-inline'` в `script-src` (`PROD_CSP`), валидация внешних URL через `isTrustedOrigin`. Директива `'unsafe-eval'` временно сохранена для `onnxruntime-web` и `litegraph.js` (техдолг **P2**: изоляция в worker) |
| Утечка API-ключей на диске | **SecretVaultService (`safeStorage` / DPAPI)** | Шифрование ключей через ОС (`safeStorage` / Windows DPAPI) в `secrets.json` (v2). При недоступности DPAPI активируется режим `session_memory_only` (ключи хранятся только в ОЗУ на время сессии, 0 байт plaintext/base64 на диске); в Renderer передаются только маски (`••••••••••••••••`) |
| Утечка секретов в логи и отчёты | **Log Sanitizer & Diagnostics Masking** | Регулярная маскировка токенов `Bearer`, ключей `sk-...`, `AIza...` и домашних путей пользователя в консоли, файлах логов и диагностических выгрузках (`maskSecrets`) |

## 3. Сообщение об уязвимостях (Vulnerability Disclosure)

Если вы обнаружили потенциальную уязвимость безопасности в A.R.C.:
- **НЕ создавайте публичный Issue** в GitHub.
- Отправьте приватный отчёт через **GitHub Private Vulnerability Reporting (Security Advisories)** репозитория: [https://github.com/DdepRest/A.R.C/security/advisories/new](https://github.com/DdepRest/A.R.C/security/advisories/new).
- Укажите затронутый компонент, версию приложения и пошаговый сценарий воспроизведения (PoC). Отчёты рассматриваются мейнтейнерами по мере поступления в порядке приоритета критичности.
